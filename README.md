# Спиральная динамика в Мармарисе

Лендинг мероприятия 1–2 сентября 2026. Astro + React + Tailwind, статическая сборка.

## Запуск

```bash
npm run dev
```

Откроется на http://localhost:4321

```bash
npm run build     # сборка в dist/
npm run preview   # посмотреть собранную версию локально
```

## Структура

```
src/
├── config/
│   └── integrations.ts   ← сюда вставляются виджеты GetCourse
├── data/
│   ├── content.ts        ← весь текст страницы
│   └── legal.ts          ← политика и оферта (для попапов)
├── components/
│   ├── LegalModal.tsx    ← единственный React-компонент
│   ├── CtaButton.astro   ← кнопка, умеет работать с GetCourse
│   ├── Nav.astro
│   ├── Hero.astro
│   └── Footer.astro
├── layouts/
│   └── Layout.astro      ← <head>, шрифты, скрипты
├── pages/
│   └── index.astro       ← сборка страницы из секций
└── styles/
    └── global.css        ← дизайн-токены (цвета, шрифты, кнопки, карточки)
```

**Правка текста** — только в `src/data/content.ts`, вёрстку трогать не нужно.
**Правка цветов/шрифтов** — блок `@theme` в начале `src/styles/global.css`.

## Как это работает (для бэкендера)

Astro рендерит все страницы в статический HTML на этапе сборки — как Django-шаблоны,
только результат складывается в файлы и раздаётся с CDN, без работающего сервера.

React подключается **островами**: интерактивный кусок помечается директивой,
и только для него грузится JS.

```astro
<LegalModal client:idle />
```

`client:idle` = «загрузи React и оживи этот компонент, когда браузер освободится».
Весь остальной текст страницы приезжает как обычный HTML и читается без единого килобайта JS.

Сейчас на странице ровно один React-остров — модалки с политикой и офертой.
Юридические тексты (≈39 KB) лежат в его чанке и не грузятся, пока модалка не нужна.

## GetCourse

Виджеты подключаются в `src/config/integrations.ts`:

1. Вписать `scriptId` и `src` из тега `<script>`, который даёт GetCourse.
2. Переключить `enabled: false` → `true`.

Пока `enabled: false`, все кнопки ведут на почту — страница остаётся рабочей.
